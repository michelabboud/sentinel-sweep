# Sentinel 2.0 Goal-Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Sentinel 2.0 as a deterministic, fail-closed QA product that performs real API and Chrome sweeps for its explicitly tested Vue Router + OpenAPI + bearer-token support matrix and produces trustworthy, redacted artifacts.

**Architecture:** A dependency-free Node.js 18 core owns filesystem boundaries, discovery, manifest validation, origin and mutation policy, secret resolution, HTTP execution, Chrome DevTools Protocol execution, findings normalization, and reporting. Claude and Codex become thin hosts for the same core; the target repository and live application remain untrusted data, while only a separately supplied operator configuration may approve origins, role mappings, parameter examples, or mutations.

**Tech Stack:** Node.js 18+ standard library (`node:test`, `fetch`, `fs`, `crypto`, `http`, `net`, `child_process`), JSON Schema draft 2020-12 within Sentinel's supported validation subset, Chrome DevTools Protocol, Bash packaging tests, Markdown/Mermaid documentation.

## Global Constraints

- Runtime dependencies: exactly zero; do not import target-repository packages or execute target-repository binaries.
- Runtime floor: Node.js 18.0.0; all production syntax must pass under Node 18.
- Release version: 2.0.0; legacy 1.x manifests fail with an explicit migration error.
- Deterministic support claim: OpenAPI 3.0/3.1 JSON, static literal Vue Router routes, bearer-token roles, and system Chrome/Chromium via CDP.
- Target repository, imported descriptions, manifests, redirects, pages, and responses are untrusted data.
- Trusted configuration must be explicitly supplied, schema-valid, non-symlinked, and outside the target root.
- No `.env`, `.env.local`, seed, credential, SSH, cloud, or arbitrary documentation reads.
- Every execution origin is exact and operator-approved; every redirect is manually revalidated.
- Every non-`GET`/`HEAD`/`OPTIONS` operation is blocked unless all six sandbox conditions in the design are true.
- Secret values may exist only in process memory and transport calls; never in return objects, errors, subprocess arguments, stdout, logs, manifests, findings, screenshots metadata, or reports.
- Every persisted file is run-scoped, atomic, mode `0600`, schema-valid, and redacted.
- Root plugin assets are canonical; `plugins/sentinel` must mirror every shipped runtime, schema, command, skill, agent, setting, and README asset byte-for-byte.
- Existing user-owned `.sentinal/` and unrelated worktree changes remain untouched.
- Each task follows RED → GREEN → REFACTOR, passes its focused tests, and ends in a commit with `Co-Authored-By: Codex <noreply@openai.com>`.
