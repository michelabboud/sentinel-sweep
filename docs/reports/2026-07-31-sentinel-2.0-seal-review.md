## Findings

### MEDIUM — CDP endpoint is unauthenticated to ANY local UID
`runtime/browser/chrome.mjs:446-447` binds DevTools to loopback TCP with an
ephemeral port. Loopback is not an auth boundary: any local account can read
`/json/version`, attach, drive the browser, and observe the role token header
(`runtime/browser/sweep.mjs:226`) for the sweep's duration. Delta-check
confirmed severity MEDIUM, non-gating: requires a hostile *other-UID* local
process during the window; assets are disposable dev/test tokens by documented
policy; identical to the default posture of Puppeteer/Playwright/Selenium.
**Actioned same-cycle:** `SECURITY.md` Chrome-boundary section now states the
exposure plainly (it previously implied a cross-UID boundary that does not
exist). **Tracked remediation:** migrate to `--remote-debugging-pipe`
(fd-based CDP, no TCP listener) — requires a pipe transport in
`runtime/browser/{websocket,cdp}.mjs`; deliberately not rushed into this
release.

### LOW (3 live, 1 void)
1. **Unbounded discovery read** — `runtime/lib/fs-boundary.mjs:289` reads
   target files with no byte cap; a multi-GB router file exhausts memory
   (fails closed; availability only). Fix: `maxBytes` on
   `TargetBoundary.readText`; a bounded-read helper already exists in
   `history.mjs:290`.
2. **Vue parser recursion depth** — `runtime/discovery/vue-router.mjs:387,411`
   can overflow the V8 stack on deeply nested literals; surfaces as opaque
   `CLI_COMMAND_FAILED`. Fix: depth counter + `VUE_DEPTH_LIMIT` diagnostic.
3. **Dead weaker `replaceLatest`** — `runtime/lib/fs-boundary.mjs:912` is
   unreachable (live path is `history.mjs:1324`, which is stronger) but skips
   the run-marker and fingerprint checks. Fix: delete it and retarget its unit
   test, so nobody wires up the weak path later.
4. ~~`.sentinal/` gitignore "typo" on main~~ — **VOID**: the directory exists
   at the repo root and `PROGRESS.md` names it user-owned with that exact
   spelling. The ignore line is correct and survives the merge unchanged.

## What held under direct attack (empirical, delta-check probes)

- **Plan integrity:** 10 constructions (forged JSON plan, structuredClone,
  in-place mutation, appended subject, prototype pollution, post-build config
  flip, getter/proxy configs, cross-engine plan, manifest-requested mutation)
  — all rejected/fail-closed. WeakMap brand keys on object identity;
  `snapshotJson` rejects proxies/accessors/foreign prototypes and rebuilds
  onto `Object.create(null)`; executors re-bind from the branded context, so
  TOCTOU is closed structurally.
- **Secret containment:** 6 leak routes (body reflection, token-as-key in
  schema pointer, content-type parameter, cross-origin redirect Location,
  thrown error message/code, oversized body) — all clean. Five independent
  layers, one more than the first pass credited: fixed-shape observations,
  path templates re-derived and enforced against the manifest, multi-encoding
  redactor at build, closed reason-code contract, and read-back verification
  that rejects if redaction would change anything.
- **Redirects** validate against the single originating origin — a bearer
  token cannot cross origins even one hop.

## Delta re-seal — post-CI-hardening (2026-07-31, `a95d7bc..c62d1c1`)

The seal above covered `a95d7bc`. Making CI green required real product fixes,
so the delta was re-audited on its own terms (Fable-tier, verified).

**Verdict: RESEAL — 0 regressions, 5/5 CONFIRMED-SAFE.**

- **Profile entropy 128→48 bits** (needed to fit the socket budget): safe, and
  never load-bearing. The guarantee is exclusive `mkdir(0700)` + post-create
  identity verification under canonical root-owned sticky `/tmp`, not name
  secrecy. A sprayed name yields EEXIST → fail closed; the socket lives inside
  a 0700 directory, so predictability gives another UID nothing.
- **`CHROME_EXITED_EARLY` now embeds stderr**: safe. Traced to
  `normalizedFailure`, where the code falls through to the fixed
  `CLI_COMMAND_FAILED` table; no finding/report/export/history path embeds
  `error.message`, and a launch failure aborts before artifacts exist.
  Pre-ready stderr predates any navigation and cannot carry credentials.
- **Browser-internal service-worker exemption**: safe. The scheme is
  parser-produced, so `blob:chrome-extension://…` and `chrome-untrusted:` do
  NOT match and stay blocked; page content cannot mint a `chrome-extension:`
  worker (registration is same-origin); the in-page `register()` override still
  blocks and reports independently. Leaving Chrome's own component worker
  running is not an isolation regression — and the exempt path skips
  `runIfWaitingForDebugger`, so such a worker stays suspended.
- **Test changes**: nothing enforced weakened; `chrome-cdp` actually *tightens*
  the profile-length bound (96→50). The crashpad/Node-floor edits were inside
  the sealed state, not post-seal delta.
- **CI environment**: relaxing the runner's AppArmor userns restriction keeps
  Chrome's sandbox ENABLED (rather than shipping `--no-sandbox`), so CI green
  still proves a sandboxed launch. Installing ripgrep makes the secret scan
  genuinely run — it failed loudly before, never silently green.

Both follow-ups the re-seal asked for are applied in this release: `SECURITY.md`
now scopes the fixed-message claim (finding messages may carry bounded
target-derived location) and documents the unprivileged-user-namespace host
requirement for stock Ubuntu 24.04.

## 2.0.1 post-release hardening — seal (2026-08-01)

The three LOW findings and the `writeCommandFailure` observation above were
implemented by a codex lane (spec: `docs/plans/2026-07-31-post-release-hardening.md`),
reviewed by the orchestrator, then sealed independently (Fable-tier, verified).

**Verdict: SHIP-2.0.1 — 6/6 CONFIRMED-SAFE, 0 defects.**

- **Bounded discovery reads preserve the descriptor-pinning contract exactly.** The
  bounded read runs on the already-pinned handle, strictly between the unchanged
  `samePinnedFile` pre- and post-checks, and the size pre-check only inspects the
  already-captured stat — no new syscall, no new TOCTOU window. Boundary arithmetic
  verified at exactly the limit, one past it, empty, and mid-read growth (all
  fail-closed). No uninitialised memory escapes `allocUnsafe` (every buffer is
  sliced to `bytesRead`), and multi-byte UTF-8 cannot be split because chunks are
  concatenated as a Buffer before a single `toString('utf8')`.
- **The depth guard is threaded through every recursive path**, and a depth-limited
  node degrades to `unsupported`, which the route/path layers strictly exclude —
  nothing depth-limited can reach execution as if it were understood. `routeAuth`
  requires a real boolean, so a degraded node can only *withhold* evidence, never
  fake it.
- **The dead `replaceLatest` had no remaining referent**; the retargeted test is a
  genuine upgrade — it exercises the live publication path, where a hostile external
  target is rejected with `LATEST_INVALID` and the victim proven untouched (the dead
  code would have silently replaced it).
- **The CLI guard runs before either output branch**, and its own failure does not
  leak: `CLI_DATA_UNSAFE` carries a fixed stage label, and `normalizedFailure`
  discards the error's message entirely.
- **The lane's correction to the spec was verified true:** `findings-contract.mjs`
  does not exist; `TRUSTED_COVERAGE_CODES` in `findings.mjs` is the only registry,
  and the bundled schemas impose no code enum. A missed registration is silent in
  the common case, which is why the new tests manufacture the secret-collision that
  makes it fail loudly.

### Found while shipping it — two release-tooling defects

Neither could surface during 2.0.0; both would have bitten every later release.

1. **`scripts/bump-version.sh` rewrote a published CHANGELOG entry.** It renames the
   top `## [x.y.z]` heading from old to new — correct when that entry is the
   unreleased one, destructive once it has shipped (running the bump before writing
   the new entry silently retitled the released 2.0.0 section). Now guarded: if a
   `v<old>` tag exists, the script refuses and states the correct order.
2. **`tests/test-version-consistency.sh` pinned `RELEASE_VERSION="2.0.0"`** and
   failed on anything else — contradicting its own header ("source of truth: VERSION
   file") and blocking every release after the one it was written for. It now
   validates VERSION's shape and holds all other surfaces to it.

### One correction to this seal's own reading

The seal reasoned that exactly 64 nested containers parse and the 65th degrades.
That is true measured from the parse entry point, but the bound is on **total**
depth, so the enclosing structure spends part of it: the routes array, the route
object, and `meta` are three containers deep before a value in `meta` is reached.
A test now pins both sides of the real boundary and the constant's comment states
the total-depth semantics — the guard behaves correctly; only the description of
where the line falls needed fixing.
